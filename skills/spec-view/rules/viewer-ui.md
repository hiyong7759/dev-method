# 설계서 보기 화면의 디자인 규칙

설계서 보기(`src/viewer/`)의 화면을 만들거나 고칠 때 지키는 규칙이다. **모양(부품·색·크기·틀·머리)은 클로드 디자인 캔버스(`.spec/config.json`의 `designCanvas`) 보드 1 "디자인 스타일 가이드라인"이 원본이다.** 여기에는 코드를 쓸 때 어기기 쉬운 규칙만 둔다. 둘이 다르면 시안을 먼저 고치고 승인받는다.

1. 화면을 만들거나 바꾸기 전에 시안을 보여 주고 승인받는다. 시안에 없는 것은 구현하지 않고, 시안과 다르게 구현하지 않는다.
2. 새 요소를 만들기 전에 기존 화면이 같은 것을 어떻게 하는지 본다. **같은 개념은 한 부품·한 자리**다: 거르기=fchips, 확인 필요=rv+확인 필요 패널, 오른쪽 열림=sidepanel, 상태=chip, 단추=btn. 화면 파일마다 따로 만들지 않고 `util.ts`의 공통 부품을 쓴다.
3. 색은 이름표(`var(--bg)`, `--text`, `--accent` …)만 쓴다. `#색값`을 소스에 직접 쓰지 않는다. 다크·라이트 값은 `style.css` 맨 위 한 곳에서만 정한다. 코드로 그리는 선·화살표도 `style.stroke = 'var(--accent)'`처럼 이름표를 쓴다.
4. 거르기는 두 가지를 섞지 않는다. 왼쪽 목록 = 분류(도메인처럼 프로젝트마다 달라지는 것), 위쪽 칩 = 상태·종류(이름이 고정된 소수). 같은 뜻을 두 자리에 두지 않는다.
5. 상단 바에는 영역·메뉴·"내 차례"·밝기 단추만 둔다. 확인 필요·메모·승인 개수 같은 이름표를 늘리지 않는다. 확인 필요는 어디서나 rv 하나, 패널 하나다.
6. 열림 메뉴(화면 ▾ 등)는 `app.ts`의 `openMenu` 하나만 쓰고, 오른쪽 패널 안에서 다시 패널을 열지 않는다.
7. 화면 머리는 한 구조(제목 + 바로 아래 한 줄 설명)다. 화면마다 제목·설명 모양을 따로 만들지 않는다.
8. 글자는 쉬운 말. 코드·태그 이름만 mono 글꼴로 보인다.
