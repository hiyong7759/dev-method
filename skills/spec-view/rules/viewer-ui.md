# 설계서 보기 화면의 디자인 규칙

설계서 보기(`src/viewer/`)의 화면을 만들거나 고칠 때 지키는 규칙이다. 시안과 부품 정의는 클로드 디자인 캔버스(`.spec/config.json`의 `designCanvas`) 보드 1 "디자인 스타일 가이드라인"이 원본이고, 이 문서는 그 요약이다. 둘이 다르면 시안을 먼저 고치고 승인받는다.

## 먼저 지킬 것

1. 화면을 만들거나 바꾸기 전에 시안을 보여 주고 승인받는다. 시안에 없는 것은 구현하지 않고, 시안과 다르게 구현하지 않는다.
2. 새 요소를 만들기 전에 기존 화면이 같은 것을 어떻게 하는지 본다. **같은 개념은 한 부품·한 자리**다: 거르기=fchips, 확인 필요=rv+확인 필요 패널, 오른쪽 열림=sidepanel, 상태=chip, 단추=btn.
3. 색은 이름표(`var(--bg)`, `--text`, `--accent` …)만 쓴다. `#색값`을 소스에 직접 쓰지 않는다. 다크·라이트 값은 `style.css` 맨 위 한 곳에서만 정한다. 화살표처럼 코드로 그리는 색도 `style.stroke = 'var(--accent)'`처럼 이름표를 쓴다.
4. 글자는 쉬운 말. 코드·태그 이름만 mono 글꼴로 보인다.

## 화면 틀과 머리

- 틀은 셋뿐이다: **목록형**(요청 목록·리포트·용어집), **분류+본문+패널형**(사용 흐름·정보 흐름), **실제 화면+패널형**(화면 설계서). 가운데 정렬 화면의 폭은 1240.
- 머리는 한 구조다: [빵부스러기] 제목(24) / 제목 바로 아래 한 줄 설명 / 오른쪽에 작업 단추. 빵부스러기는 두 단계 이상 들어간 화면(요청 상세, 정보 변경, 전후 비교)에만. 오른쪽 패널 안에서는 같은 구조를 제목 18로 줄여 쓴다.
- 한 줄 설명은 목록·흐름 화면은 "이 화면이 왜 있는지", 상세는 이름표와 출처, 화면 설계서는 그 화면의 존재 이유(`@why`).

## 거르기

- **왼쪽 목록(side-list, 폭 200)** = 분류. 도메인처럼 프로젝트마다 이름과 개수가 달라지는 것. 주소는 `?domain=`.
- **위쪽 칩(fchips)** = 상태·종류. 전체·화면용·내부용·확인 필요처럼 이름이 고정된 소수. "전체"가 맨 앞, 하나만 선택, 상태는 주소에 둔다. 만드는 곳은 `util.ts`의 `filterChips`.
- 분류가 있는 화면(사용 흐름, 정보 흐름)은 둘 다, 없는 화면(요청 목록, 리포트)은 칩만 쓴다. 같은 뜻을 두 자리에 두지 않는다.

## 부품

| 부품 | 규칙 |
|---|---|
| 상단 바 | 높이 62. 왼쪽부터 DEV · 프로젝트 이름 · 현행\|관리 · 그 영역의 메뉴. 오른쪽 끝에는 "내 차례 N"과 밝기 단추(◐)만. 확인 필요·메모·승인 개수는 올리지 않는다 |
| 밝기 단추 | 누르면 다크·라이트·시스템 세 줄 메뉴. 기본 시스템, 고른 값은 브라우저에 저장(`theme.ts`) |
| 탭 | 화면 설계서의 개요·현행·히스토리 세 개뿐. 다른 구분은 탭이 아니라 거르기 줄 |
| chip(이름표) | 상태를 한두 단어로. me=노랑(내 차례), ag=파랑(에이전트 차례), ok=초록, bad=빨강, dim=회색 |
| tag(태그) | 범위·종류. 파랑=화면·컴포넌트, 초록=정보 |
| btn(단추) | 주(파랑)=설계 승인, ok(초록)=테스트 승인, bad(빨강)=반려·삭제, sm=작은 크기, off=못 누름, 새 창으로 열기는 "↗" |
| rv(확인 필요) | 어디서나 같은 모양의 작은 노랑 이름표. 누르면 **같은 확인 필요 패널**이 열린다. 상단 바에는 올리지 않는다 |
| card / box | 칸 / 칸 안의 칸. 경고는 warn, 안내는 hint, 이름-값은 kv |
| sidepanel | 오른쪽 열림. 폭 380 고정. 제목+✕ / 본문 칸들 / 아래 단추. Esc로 닫고, 패널 안에서 다시 패널을 열지 않는다 |
| 메뉴 | 상단 "화면 ▾" 같은 열림 목록은 `app.ts`의 `openMenu` 하나만 쓴다 |

## 색에 뜻 하나

- 파랑=기본 흐름·선택됨·에이전트 차례, 노랑=내 차례·갈래·확인 필요·바뀌는 곳, 초록=완료·통과·추가·정보, 빨강=문제·반려·삭제·오류. 점선=되돌아가기·"아직 아님"(의도 없음 포함).
- 뜻 없는 색은 쓰지 않는다. 실제 앱 화면이 들어가는 자리만 두 모드 모두 밝은 바탕.

## 크기

- 글자 24(제목) / 15~16 / 13~14(본문) / 12 / 11. 간격 4·8·12·16·24. 모서리 999(알약) / 8~10 / 12(칸).

## 빈 상태·오류·툴팁

- 빈 상태는 "왜 비었는지 + 다음에 할 일" 한 줄. 오류는 빨강 칸에 원인과 다시 시도. 툴팁은 우리 용어집에 있는 용어에만.

## 흐름 그림(사용 흐름 전용)

- 단계 칸은 번호+일+자리. 파랑 실선=기본 흐름, 노랑 실선=조건에 따라 갈라지는 길, 점선=앞 단계로 되돌아오는 길.
