# 도구가 읽는 것과 읽히게 쓰는 법

도구는 `extract.mjs`(주석 태그)와 `analyze-ts.mjs`(TypeScript)다. 에이전트는 아래 모양으로 써야 도구가 읽는다.

| 알아내는 것 | 읽는 방식 | 이렇게 써야 읽힌다 |
|---|---|---|
| 정보 목록, 필드 | TypeScript 언어 서비스로 export된 `interface`·`type`·`enum`을 모은다 | 정보는 export된 이름 있는 타입으로 정의한다 |
| 필드를 읽고 쓰는 곳 | 필드 단위 참조 분석(읽기·쓰기 구분), 쓰는 파일·영역 | 파생 타입은 `Pick`·`Partial`·`Omit`으로 만들고, 필드 이름 문자열은 `keyof`로 묶는다 |
| 정보 필드의 존재 이유 | 정의 바로 위 주석 | 필드마다 바로 위에 `/** 한 줄 */`로 쓴다 |
| 화면·컴포넌트·로직의 존재 이유 | 주석 태그 `@screen`·`@spec`·`@why`·`@basis`·`@contract`·`@anchor` | 블록 주석 안에서 태그로 시작하는 줄을 쓰고, 값이 길면 다음 줄에 이어 쓴다 |
| 틀릴 수 있는 곳 | 쓰기·읽기가 안 보이는 필드는 같은 이름의 다른 정의와 문자열 참조를 근거로 "후보"로 표시한다 | 같은 정보를 손으로 다시 정의하지 않는다 |

```ts
export interface TripItem {
  /** 같은 날 안에서 일정의 순서와 이동 시각을 알리려고 */
  assignedTime?: string;
}
```

```tsx
/**
 * @screen Day 상세
 * @why 하루 일정을 시간 순서로 보고, 예약 여부와 시각을 바로 고치게 하려고
 */
```

## 화면·이동·동작은 지금 태그로 선언한다 (임시 선언)

도구가 코드에서 아직 못 읽는 것(화면 주소, 화면 사이 이동, 이벤트와 동작, 사용자가 하는 일)은 주석 태그로 선언한다. 라우터 정의(routes.ts 등)에서 읽을 수 있게 되면 이 태그를 지운다. 도구를 고치면 이 표도 같은 커밋에서 고친다.

| 어디에 | 태그 | 뜻 |
|---|---|---|
| 화면(`@screen 이름`) | `@route /trips/:tripId` | 라우트 패턴. 설계서 보기가 실제 화면을 끼워 넣고, 앱 안 주소와 화면을 맞출 때 쓴다 (필수) |
| | `@sample /trips/t1` | 주소 변수가 있을 때 지도에서 화면을 열 실제 주소 |
| | `@domain 여행` | 전체 지도에서 묶어 보는 이름 |
| | `@start` | 시작 화면 표시(없으면 들어오는 길이 가장 적은 화면) |
| | `@does 사용자가 하는 일 \| 확인 기준` | 한 줄에 하나씩. 승인 때 확인 목록이 된다 |
| | `@to 대상 화면 \| 행동 \| 넘기는 값` | 한 줄에 하나씩. 대상은 다른 `@screen` 이름과 같아야 한다(끊긴 참조는 경고) |
| 컴포넌트(`@spec`) | `@on 이벤트: 효과` | 한 줄에 하나씩. 이벤트 핸들러가 있으면 필수 |
| 정보 타입의 JSDoc | `@nonInfo 이유` | 정보가 아닌 타입(이동 약속, 화면 설정 등). 정보 흐름과 존재 이유 검사에서 뺀다 |
| 정보 필드의 JSDoc | `@ref 대상.필드` | 값으로만 가리키는 약한 연결 |

`@to`는 `nav.mjs`가 코드의 실제 이동과 대조한다. 선언했는데 코드에 없거나, 코드에 있는데 선언이 없으면 경고다(전체 지도에는 "코드에서 못 찾음"으로 보인다). 이동 설정은 `.spec/config.json`의 `navigation: { routes: "ROUTES", helpers: ["toPath"] }`로 바꾼다.

컴포넌트가 어느 화면에 속하는지는 도구가 계산한다(화면 파일에서 상대 경로 import로 닿는 파일에 있으면 그 화면). 필드를 보여주거나 입력·수정하는 화면은 타입 참조 분석으로 읽고, 새 값을 만드는 쓰기는 "입력", 있던 값을 고치는 쓰기(대입, `...펼침`을 쓴 새 객체)는 "수정"으로 나눈다. 이 구분은 코드 모양으로 추정한 것이다.
