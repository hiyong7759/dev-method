# 새 요청을 등록할 때 (접수 절차)

새 요청을 등록하려는 세션은 어떤 세션이든 `request add` 전에 이 순서를 따른다. 합칠 것을 찾는 일이 한 세션의 역할이 아니라 등록 절차 자체에 있다. 목적은 같은 일을 요청 여러 개로 나눠 담당 세션을 여럿 만들지 않아 비용을 줄이는 것이다.

1. 후보 찾기: `request similar [--screens …] [--infos …] [--scenarios …] --src <소스 폴더>`. 접수·설계 작성 중인 요청만 본다. 후보 기준은 (1) 같은 화면·정보·시나리오를 건드림, (2) 둘 다 범위를 적지 않은 작은 일(설계 없음으로 끝날 것). 이미 접수된 요청끼리 합칠 것도 함께 보려면 `--all true`
2. 후보가 있으면 근거와 함께 사용자에게 "#N에 합칠까요?"를 묻는다. 후보는 제안일 뿐이고 합치는 결정은 사용자가 한다
3. 합치기로 정하면 사용자가 한 말을 인용해 합친다
   - 새 요구를 기존 요청에: `request merge --into 남는번호 --text "새 요구" --quote "사용자가 한 말"`
   - 이미 접수된 두 요청을: `request merge --into 남는번호 --from 없어질번호 --quote "…"` (없어지는 요청은 "#N에 합침"으로 닫히고 번호·커밋 기록은 이어진다)
4. 합치지 않기로 했거나 후보가 없으면 `request add`로 새로 접수한다

## 합칠 수 있는 때

- 접수, 설계 작성 중인 요청만 합친다. 설계가 승인 대기에 올라갔거나 승인된 요청은 사용자가 본 설계를 몰래 바꾸지 않도록 합치지 않는다. 이때는 새 요청으로 접수하며 `request add --related 기존번호`로 이어 둔다
- 담당 세션이 설계를 쓰는 중인 요청에 합치면, 그 세션이 다음에 움직일 때 새 요구가 합쳐졌다는 알림이 간다(inbox 훅)
- 양쪽에 담당 세션이 있는 두 요청을 합칠 때는 번호가 작은 쪽을 남긴다
