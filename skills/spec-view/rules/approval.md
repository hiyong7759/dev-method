# 승인

- 화면 상태는 개발 중, 테스트 요청, 수정 필요, 승인됨, 승인 후 변경됨이다
- 에이전트는 작업을 끝낼 때 SKILL.md "끝낼 때" 1~3을 통과하면 화면을 "테스트 요청"으로 기록하고, 메시지를 남긴다. 메시지에는 이번에 새로 만들었거나 바뀐 것과 특히 봐 달라는 점을 쓴다. 웹 프로젝트는 설계서 보기가 실제 화면을 옆에 보여 주므로 여는 방법을 쓰지 않고, 실제 화면을 끼울 수 없는 프로젝트(네이티브 앱 등)만 실행·확인 방법을 함께 쓴다
- 사용자는 확인 목록(화면 메타정보 `@does`에 쓴 "사용자가 하는 일")을 실제 화면에서 눌러 보고, 문제는 오류 메모로 남기거나 승인한다. 승인은 사용자만 한다
- 승인하면 승인한 사람·시각·소스 버전이 기록된다. 그 뒤 화면의 소스가 바뀌면 자동으로 "승인 후 변경됨"이 되어 다시 확인을 받는다

## 기록하는 법

- 상태는 프로젝트의 `.spec/status.json`에 화면별로 남고, 이력(상태, 누가, 언제, 커밋, 메모)이 쌓인다. 이 파일은 커밋한다
- 에이전트는 `status.mjs set dev|test-requested --screen <화면 이름>`만 쓴다(화면이 하나면 `--screen` 생략). 승인됨·수정 필요는 명령이 거부한다. 사용자가 설계서 보기의 승인 탭에서만 남긴다
- 확인 목록(`@does`)의 체크 상태는 `.spec/status.json`에 남고, 테스트 요청을 다시 하면 비워진다. 모두 체크해야 승인 버튼이 켜진다. "문제 있음"은 오류 메모를 만들고 상태를 수정 필요로 바꾼다
- 테스트 요청을 남길 때(finish가 통과한 직후)와 승인할 때의 화면이 `.spec/shots/`에 저장된다. 히스토리의 변경을 누르면 그 변경 직전·직후에 저장된 화면이 "변경 전 / 변경 후"로 나란히 나온다(두 시점 사이에 다른 변경이 섞일 수 있다). 그래서 finish를 돌린 직후에 `status.mjs set test-requested`를 해야 화면이 붙는다
- 승인하면 그 순간의 화면 스크린샷이 기준 화면으로 `.spec/shots/`에 저장되고, 승인 후 변경됨 카드에 "승인 때 / 지금"으로 나란히 보인다
- "승인 후 변경됨"은 기록하지 않고 계산한다: 화면 파일과 거기서 상대 경로로 import하는 파일의 내용이 승인 때와 다르면 된다
- 상단 상태 칩, 승인 탭의 점, 화면 흐름 카드가 테스트 요청·승인 후 변경됨일 때 깜빡인다
