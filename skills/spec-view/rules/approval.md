# 승인 (요청 단위)

승인은 화면마다 하지 않고 **요청 단위**로, **사용자만** 한다. 요청 하나는 설계 → 구현 → 테스트 → 완료를 거치고, 설계와 테스트에서 사용자 승인이 필요하다. 모든 변경은 요청 번호가 있어야 한다.

## 에이전트가 하는 일 (명령은 `node <스킬 폴더>/spec.mjs request <명령> --src <소스 폴더> …`)

1. **요청을 받으면** `request add --title "…" --origin "사용자가 한 말" --screens … --infos … --scenarios …`로 등록한다. 범위는 사용 시나리오 기준이다(`--scenarios`), 이번 요청이 바꾸는 단계는 `--steps "시나리오#단계,…"`, 바꾸지 않고 영향만 볼 시나리오는 `--impact`. 맡은 세션 이름은 `request agent --id N --name …`
2. **설계**: 정보나 화면이 바뀌면 설계를 올린다. `request design --id N --file 설계.json`. 파일 모양은 `understanding`(이렇게 이해했다: 짧은 한 줄 요약), `points`(영역별 항목: area 영역, title 바뀌는 것, text 설명 — 화면이 영역·바뀌는 것·설명 표로 보인다. 글 기호는 쓰지 않는다), `approach`(이렇게 처리하겠다: 정보·화면 변경이 없는 "설계 없음" 요청에서만 쓰고 보인다), `changes`(정보 변경: info, kind add|remove|change|link, field, note — 화면에는 정보 하나에 한 줄 요약으로 보이고 자세한 것은 "정보 변경 겹쳐 보기"), `screens`(화면 디자인: screen, after 시안 그림 파일, note, counts, highlights 현행과 달라진 곳의 위치·이름, isNew), `data`(이미 있는 데이터·되돌리기·실제 데이터). 정보도 화면도 안 바뀌면 `request design --id N --none true`("설계 없음")
   - **현행과 시안**: 비교하는 "현행"은 지금 운영 중인 화면을 손대지 않고 그대로 찍은 것이어야 한다. 행을 숨기거나 지우거나 글자를 바꿔 찍지 않고, 지난 시안을 현행으로 쓰지 않는다. 고친 모습은 `after`(시안) 그림에만 얹는다. 현행은 `request shot --id N --screen 화면이름 --url 운영 화면 주소 [--selector css]`로 찍는다(ego-browser로 열어 찍고, 도구가 찍은 시각과 주소를 남기고, 설계를 올릴 때 이 그림이 현행으로 붙는다). 파일로 직접 올린 `before`는 "손으로 올림(현행이 아닐 수 있음)" 경고가 붙는다
   - **신규 화면**: 설계서 보기에 아직 없는 새 화면은 `isNew: true`로 올린다. 현행 그림 없이 받고, 설계 결과 칸에 "신규 화면" 이름표와 시안만 보이며 "현행과 비교" 단추가 없다. 이미 있는 화면인데 현행 그림이 없으면 설계를 올릴 수 없다
3. **승인 전에는 구현하지 않는다.** 사용자가 설계 승인(또는 설계 없음 승인)을 하면 `request impl --id N [--commit 해시]`로 구현을 기록한다. 반려되면 이유를 읽고 설계를 고쳐 다시 올린다
4. **끝낼 때**: SKILL.md "끝낼 때" 1~3(finish 통과, 스크린샷 확인)을 통과한 뒤 `request test --id N`으로 테스트를 올린다. 테스트하다 범위 밖에서 발견한 것은 `request found --id N --text "…"`(리포트로도 올라간다). 사용자가 테스트를 반려하면 같은 요청에서 고치고 다시 `request test`
5. 코드로 알 수 있는 것은 코드에서 계산한다. 사람이 적는 것은 코드로 알 수 없는 것뿐이다

## 사용자가 하는 일 (설계서 보기 "관리")

- 설계 승인: 정보 변경과 화면 디자인을 확인(체크 두 개)하고 승인하거나, 이유를 한 줄 적어 반려한다. "설계 없음"도 사용자가 승인한다
- 겹치는 요청이 있으면 끝나는 순서를 정한다("#12 먼저")
- 테스트 승인: 요청의 사용 시나리오 확인표를 실제 화면에서 눌러 보고 체크한 뒤 승인하거나 반려한다. 시나리오가 없으면 "테스트 없음"으로 승인할 수 있다
- 승인·반려·순서·체크는 설계서 보기 서버가 받는다. 에이전트용 명령은 반려·순서·체크를 할 수 없다. 승인만은 아래 "대화에서 한 승인"으로 기록할 수 있다

## 대화에서 한 승인

- 사용자가 시안이나 설계를 대화에서 승인했으면("그대로 확정", "진행해" 등) 그 말을 요청의 승인으로 가져간다. 에이전트가 `request design`으로 설계를 올린 뒤 `request approve-design --id N --quote "사용자가 한 말"`로, 테스트도 같은 식으로 `approve-test --quote`로 기록한다
- 인용은 **그 요청에 대한 사용자의 말만** 쓴다. 일괄 지시나 다른 요청의 말을 인용해 승인하지 않고, 방금 구현을 끝낸 요청의 테스트는 사용자가 확인하기 전에 승인하지 않는다
- 설계를 올릴 때 화면 변경은 현행 그림(before)과 변경 후 그림(after)을 함께 올린다(현행이 없으면 "현행과 비교해서 보기"가 비어 사용자가 비교하지 못한다). 올린 뒤 승인 화면과 비교 화면을 직접 열어 현행과 변경 후가 모두 읽히는지 확인하고 나서 승인을 요청한다
- 인용(사용자가 한 말 그대로)이 없으면 기록되지 않는다. 인용은 요청 상세의 진행 기록에 그대로 보인다. 사용자가 승인하지 않은 것을 에이전트가 승인하지 않는다(반려도 이 명령으로는 못 한다)

## 사용자 결정이 담당 세션에 전달되는 방법

- 사용자의 승인·반려·순서 정하기는 요청 파일에 기록된다. 담당 세션은 감시기 없이 **훅**(`spec.mjs inbox`, `./install.sh agent-hook <프로젝트>/.claude/settings.json`으로 등록)으로 받는다
- 세션이 `request agent --id N`을 실행하면 훅이 그 세션을 요청 N의 담당으로 적는다(요청을 접수만 하는 `request add`는 담당으로 적지 않는다. 접수한 세션이 담당이 되면 시작할 때 담당 세션이 만들어지지 않는다)(`.spec/sessions.json`, 커밋하지 않음). 그 뒤 사용자가 말을 걸 때와 도구를 쓴 뒤에 새 결정이 있으면 "이어서 할 일"과 함께 알려 준다. 세션이 완전히 쉬고 있으면 사용자가 `claude attach <이름>`으로 들어가 말을 걸 때 전달된다
- **담당 세션은 서버가 만들고 깨운다**(`src/session.ts`·`src/wake.ts`, 기본 꺼짐). 프로젝트 설정 `.spec/config.json`에 `"wake": true`를 쓰면 다음이 켜진다. ① **시작**: 접수된 요청을 사용자가 화면의 "시작" 단추나 `request start --id N`으로 시작하면 그 요청만 맡는 새 세션을 `claude -p 글 --session-id 새번호`로 만들고(`.spec/sessions.json`에 바로 적음), 그 세션이 담당을 등록하고 설계를 써서 올린 뒤 승인 대기에서 멈춘다. 담당이 이미 있으면 새로 만들지 않는다. ② **결정**: 사용자가 승인·반려·순서를 정하면 담당 세션이 지금 일하는 중인지 `claude agents --json`으로 보고, 일하는 중이 아니면(VS Code나 터미널에 열어 두고 기다리는 세션, 일을 마치고 쉬는 세션, 오래된 세션) 그 세션에 글을 보낸다. 1시간 넘게 쉬어 캐시가 식었거나 대화 기록이 500KB 넘게 클 때만 먼저 `claude -p "/compact" --resume 세션`으로 압축한 뒤 "요청 파일과 `todo` 명령을 읽고, 결정된 그 일만 하고 끝나면 멈추세요"를 보낸다(압축만으로는 움직이지 않아 두 번 부르고, 압축이 실패해도 두 번째는 보낸다). 일하는 중인 세션은 서버가 같은 대화에 끼어들지 않고 위의 훅에 맡긴다(곧 도구를 쓰므로 그때 전달된다. 기다리는 세션은 훅이 움직일 수 없어 직접 보낸다). 결정이 전달되지 않았으면 `request wake --id N`으로 마지막 결정을 다시 보낸다(일하는 중인 세션에도 보낸다). 담당 세션이 한 번도 없었으면 새로 만들어 그 일을 맡긴다. 세션은 읽기·고치기·`node`·`npm`과 그 일의 `git add`·`git commit`을 쓸 수 있고, 위험한 git은 차단 훅이 막는다. **비용**: 만들거나 깨울 때마다 claude 결과에서 토큰과 비용을 읽어 `.spec/session-costs.json`(커밋하지 않음)에 적고(`cost` 명령), 요청 상세 "맡은 에이전트" 칸에 합계와 횟수가 보인다. 결과는 `.spec/wake.log`에 남고, 시작·깨우기가 실패해도 사용자의 시작·결정은 그대로 처리된다
- 에이전트는 알림이 올 때까지 기다리지 않고, 승인이 필요한 단계에서는 "승인 대기"라고 사용자에게 알리고 멈춘다

## 기록

- 요청 하나가 `.spec/requests/<번호>.json` 파일 하나다(진행 기록, 설계, 테스트 확인, 구현 커밋). 설계 그림은 `.spec/shots/`에 저장된다. 둘 다 커밋한다
- 화면 승인과 화면 상태(개발 중·테스트 요청·승인됨)와 메모는 없앴다. 화면 설계서의 히스토리는 그 화면을 바꾼 요청(설계 승인, 구현 커밋, 테스트 승인)과 요청 번호 없이 남은 변경을 보인다
