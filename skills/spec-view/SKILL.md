# 설계서 보기 (소스가 설계서)

목적: 설계서를 따로 쓰지 않는다. 소스의 메타정보(존재 이유)와 도구(`extract.mjs`, `analyze-ts.mjs`, `nav.mjs`, 설계서 보기 서버 `serve.mjs`)가 설계서를 만든다. 도구 위치: 이 폴더. 아래 순서를 건너뛰지 않는다.

## 설계서 보기

서버 주소(기본 `http://localhost:5290`)를 열면 설계서 보기가 나오고 첫 화면은 화면 흐름이다. 상단 내비게이션 하나로 화면 흐름, 정보 흐름, 모든 화면(`화면 ▾`), 모든 정보(`정보 ▾`)에 간다. 화면 설계서는 실제 화면 + 개요·컴포넌트·메모·승인·히스토리 탭이다. 앱 주소를 직접 열면 그 화면의 설계서로 간다. 전부 소스에서 계산하며, 저장하는 것은 프로젝트 `.spec/`의 승인 기록·확인 목록·메모·스크린샷뿐이다(`.spec/`은 커밋한다).

설계서 서버(`serve.mjs`)는 프로젝트의 앱 개발 서버를 중계하면서 그 위에 설계서를 얹는다. 프로젝트에 설치하는 것은 없고 어떤 개발 서버든 같은 방식이다. 앱 개발 서버 설정(vite 등)에 이 도구의 플러그인을 넣지 않는다(예전 `vite-plugin.mjs`를 쓰던 프로젝트는 vite.config에서 지운다).

### 설계서 띄우기

사용자가 "<프로젝트> 설계서 띄워", "화면설계서 보여 줘"처럼 말하면 이 한 줄을 실행하고 주소를 알려 준다:

`node <이 폴더>/open.mjs <프로젝트 이름 또는 폴더>`

- 앱 개발 서버가 꺼져 있으면 `.spec/config.json`의 `start`(기본 `npm run dev`)로 띄우고, 설계서 서버를 띄운 뒤 브라우저를 연다. 이미 떠 있으면 그대로 쓴다. 이름은 `install.sh spec`으로 등록한 프로젝트 폴더 이름이다
- 에이전트가 끝낼 때 확인용으로 띄울 때는 `--no-open`. 끄려면 `--stop`
- 설정 `.spec/config.json`: `src`(소스 폴더), `app`(앱 개발 서버 주소), `port`(설계서 서버, 기본 5290), `start`

## 원칙

- 코드에 이미 있는 것(정의, import, 읽기·쓰기)은 도구가 읽는다. 에이전트가 쓰는 것은 코드에 없는 것(존재 이유, 근거, 약속, 동작의 의미)뿐이다. 같은 사실을 두 번 쓰지 않는다
- 존재 이유는 에이전트가 쓰고 사용자가 검토한다. 코드로 확인한 것만 쓴다
- 타입 선언이 가능한 언어를 기본으로 한다
- 도구가 못 읽는 구조는 읽히게 고친다. 정 안 되면 임시로 선언하되 경고로 남긴다

## 순서

0. **프로젝트 처음 한 번**: `<dev-method>/install.sh spec <프로젝트> <소스 폴더> <앱 개발 서버 주소> [포트]`로 `.spec/config.json`을 만들고, 프로젝트 이름을 등록하고, 경고 0 커밋 검사를 연결한다

1. **시작**: 작업 범위(그 화면, 그 정보)를 정한다. 코드를 처음부터 분석하지 말고 `node <이 폴더>/extract.mjs <소스 폴더>`의 요약과 `--check` 경고를 먼저 읽는다. 프로젝트 전체를 읽지 않는다
2. **만드는 중**: 해당하는 규칙 파일만 읽는다. 새로 만드는 것에는 필수 메타정보를 함께 쓴다
   - 메타정보 종류와 필수·선택 → `rules/meta.md`
   - 정보(타입) → `rules/info.md`
   - 화면, 컴포넌트 → `rules/screen.md`
   - 화면 없는 모듈 → `rules/logic.md`
   - 태그 문법과 도구가 읽는 방식 → `rules/tools.md`
3. **변경 요청을 받았을 때**(메모, 대화): `rules/request.md`
4. **끝낼 때**(통과해야 "테스트 요청"을 쓸 수 있다):
   1. `open.mjs <프로젝트> --no-open`으로 서버를 직접 띄운다 (사용자에게 띄우라고 하지 않는다)
   2. 프로젝트 루트에서 실행한다: `node <이 폴더>/finish.mjs --routes <확인할 주소들, 쉼표>` (소스 폴더와 서버 주소는 `.spec/config.json`에서 읽는다)
      - 하는 일: 메타정보·정보 존재 이유 경고 0, 이동 선언(`@to`)이 코드의 실제 이동과 같은지, 설계서 서버 응답과 첫 화면이 화면 흐름인지, `@route`가 주소와 맞는지, 화면 설계서가 열리는지, 실제 화면이 열리고 오류가 없는지, `@anchor`가 실제 화면에서 찾히는지. 스크린샷도 남긴다
      - 처음 쓰는 컴퓨터에서는 이 폴더에서 `npm install`을 한 번 한다(컴퓨터의 Chrome을 쓴다)
   3. 스크린샷을 직접 보고 방금 만든 화면과 설계서 보기 카드가 의도대로인지 확인한다. 스크립트는 열리는지만 본다
   4. 확인한 것만 근거로 화면 상태를 기록한다: `node <이 폴더>/status.mjs set test-requested --src <소스 폴더> --screen <화면 이름> --note "확인 방법 한 줄"` → `rules/approval.md`
   - 2번이 실패했거나 3번을 하지 못했으면 상태는 "개발 중"이다. 사실대로 보고하고 테스트 요청을 내지 않는다

## 보고

사용자는 기획자다. 전문 용어는 풀어 쓴다. 보고는 세 덩어리로 나눈다.
- **확인할 것**: 사용자가 화면에서 눌러 볼 것과 기대 결과
- **결정할 것**: 사용자만 정할 수 있는 것. 없으면 "없음"
- **처리한 것**: 에이전트가 알아서 한 일(도구 고침, 경고 해결 등)은 한두 줄로 줄인다. 파일 경로는 꼭 필요한 것만 쓴다
