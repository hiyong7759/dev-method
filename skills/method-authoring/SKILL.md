# 정책을 어디에 둘까

CORE.md는 모든 프로젝트에서 늘 읽히므로 핵심만 둔다. 자세한 내용은 별도 장치로 나눈다. 모든 경우를 지금 식별할 수 없으니 쓰면서 고친다.

## 장치 고르기

- **매 작업에 해당하는 원칙** → CORE.md 한 줄. 이유·예·절차는 쓰지 않는다
- **기계적으로 가려지는 것**(비밀번호, 위험한 git 명령, 알림) → 훅·스크립트. 문장으로 부탁하지 않는다
- **특정 순간에만 필요한 깊이** → 그 순간 하나에만 걸리는 작은 스킬. 설명(description)에 그 순간 하나를 쓴다
- 서로 다른 순간을 한 스킬에 묶지 않는다. 설명이 흐려져 안 읽히거나, 읽혀도 필요 없는 내용이 딸려 온다

## 쓸 때 지킬 것

- 한 사례에만 강한 규칙은 다른 사례를 방해한다. 사용자 선호가 아니라 에이전트가 사건 하나를 겪고 만든 대응이면 CORE에 넣지 않는다
- 미래 조건("~가 생기면 다시 정한다")은 CORE 문장으로 두지 않는다. 다시 볼 시점은 트리거(스킬이 걸리는 순간, 날짜 있는 메모)에만 둔다
- 히스토리·기각·출처 인용은 CORE가 아니라 커밋 메시지에 남긴다
- 고친 뒤 실제로 읽히는지, 지켜지는지는 쓰면서 본다. 안 읽히면 내용이 아니라 장치를 바꾼다
- 바꾸는 것은 사용자 확인 뒤에 한다
